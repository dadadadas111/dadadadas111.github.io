A 20-person IoT startup. I am the only engineer on the cloud side, so the dashboard, the API, the message pipeline and the deploy path are all mine. The platform serves 640k users and 69k devices for 26 partner projects, at roughly 2.6M API requests a day and 15.5k concurrent MQTT connections.

  • I build both ends of the partner dashboard, the Next.js pages and the NestJS endpoints behind them. The organisations area is mine end to end: list and detail pages, an invite flow that finds members by email, project assignment, and the API and data model underneath.
  • One deployment serves 26 partner projects, so a lot of the work is access control. I own the authorisation rules on the server and the matching checks in the React app, so a partner is not offered an action the API would refuse. Settings that used to be global, such as the SMS provider, are now configured per project, with the setup page reduced to three questions.
  • I run the pipeline that carries device state. Partner traffic used to go through one Kafka broker with no replication, so I moved it onto a replicated three-broker cluster with a separate listener for partner systems. The consumer merges repeated state updates instead of writing every one.
  • There was no monitoring when I started. Prometheus, Loki and Grafana now cover the three clusters with the AWS side pulled in from CloudWatch, so an incident starts at a dashboard instead of a guess. I also own the staging to production path across four repositories.
  • Most of my performance work has been finding the cause rather than writing anything clever. A device query took eleven minutes because nothing was indexed behind a $lookup, and the plan had been to pay for a bigger database tier instead. Auth middleware was verifying a token signature on every request. A partner SDK sent everything at once on the hour. Each fix was small once the cause was clear.
  • Smaller things that made the work easier for everyone: the test suite had been abandoned because running it exhausted memory, so I moved it to Jest 29 with transpile-only tests and put it back in CI; the dashboard now survives a CMS outage instead of crashing, and shows the deployed commit in a corner badge.
