Experience

Full-Stack Engineer at Rogo Solutions JSC

Jan 2024 to present · Hanoi

A 20-person IoT startup. I am the only engineer on the cloud side, so the dashboard, the API, the message pipeline and the deploy path are all mine. The platform serves 640k users and 69k devices for 26 partner projects, at roughly 2.6M API requests a day and 15.5k concurrent MQTT connections.

  • Permissions are attribute based. A partner's rights are stored as resource and action pairs scoped to a project, then encoded into a short string so the whole set fits inside a Firebase custom claim and travels with the ID token, which auth middleware decodes per request. The dashboard builds CASL abilities from the same data, so the interface only offers actions the API would accept. I wrote v2 of this and the migration off v1.
  • Device state moves over MQTT into Kafka and out to MongoDB. The consumer buffers and coalesces repeated updates rather than writing per message, and commits its offset after the write, so losing a pod costs latency rather than data. KEDA scales it between 2 and 12 replicas on consumer group lag, with a floor of two so a node drain does not leave the topic unconsumed. Partner traffic used to run through a single unreplicated broker.
  • There was no monitoring when I started. Prometheus, Loki and Grafana now cover the three clusters with the AWS side pulled in from CloudWatch, so an incident starts at a dashboard instead of a guess. I also own the staging to production path across four repositories.
  • The test suite had been abandoned because running it exhausted memory and froze dev machines, so nothing was gated on it. Moving to Jest 29 with transpile only tests and a separate type check brought it back to a few seconds, and back into CI. The dashboard also survives a CMS outage now instead of crashing.
